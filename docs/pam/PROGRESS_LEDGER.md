## Lessons
- The PAM branch lives in a linked git worktree (`pam-worktree`), not the main checkout — `git worktree list` from REPO_ROOT is the fastest way to find in-flight branch work; file mtimes and directory names mislead.
- Merging `main` into the PAM branch conflicts in `services/auth/internal/http/handlers.go` whenever main hardens auth (it did: per-IP limiter P1-05). Resolution pattern: keep main's additions AND the 3-arg `Login(..., otp)` signature; `firstNonEmpty` now comes from main's copy (P0-1's trailing duplicate was dropped in the merge).
- Husky pre-commit runs the FULL frontend unit suite (`lerna run test`) + lint-staged on every commit (~2 min) and a post-commit commitlint that complains about old commits — its failure does not block the commit. Budget commit time; use timeout ≥300s.
- The auth test harness pattern: `t.Setenv` for seed users + `NewAuthService()` + `RegisterRoutes` + `httpx.Chain(...)`; `totpCode(secret, time.Now())` from totp.go generates valid codes in tests. Suite is bcrypt-slow (~3 min with -race) — run targeted `-run` filters while iterating.
- The gateway already has a fail-closed services toolkit (`internal/compliance/fail_closed.go`) that nothing uses — check for existing dead "correct" implementations before writing new ones.
- The backoffice Playwright harness had been dead since the office moved to the App Router: the auth setup drove a mock login at a route that 404s, ports 3000/3002 could never bind on this machine (other projects' dev servers), and `reuseExistingServer: true` will happily "reuse" a FOREIGN process on the expected port — always verify what is actually listening before trusting a green webServer.
- Backoffice e2e now requires the local Go stack: scratch Postgres (`docker run … -p 5436:5432 postgres:16` + `cmd/migrate up` + `cmd/seed`), auth `:18081` (`AUTH_STORE_MODE=db`), gateway `:18080` (`WALLET_STORE_MODE=db`), then `E2E_OFFICE_PORT=<free port> npx playwright test -c playwright.config.ts --project=backoffice`.
- This machine's ports are crowded (3000 LOCKIN, 3100 wellnest-sim, 5434 stale docker bind, 5435 attaboy) — always `lsof` a port before assigning it; never kill the occupants, they are the user's other projects.
- Shell cwd drifts between Bash calls after failed `cd`s — start every command from an absolute path.
- The office has a guard test `tests/app-router-legacy-routes.test.ts` asserting specific `(dashboard)` routes STAY redirect-to-dashboard stubs (`/reports`, `/campaigns`, `/risk-management` are intentionally beta-hidden sportsbook-era surfaces). Don't reactivate a guarded route to hang new work on it — use a fresh route (P1-6 exports live at `/exports`, not `/reports`). The husky pre-commit runs office `vitest` (131 tests) so this fails the commit, not just CI.
